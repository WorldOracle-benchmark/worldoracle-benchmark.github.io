01 · Get started

Submission Overview

Register one account for one participating team and one fixed model. After email verification and organizer review, that model can submit multiple versions to Main, Policy, and Long-Horizon Tracks. Open-weight and closed-source approaches may both participate; public resources and certification are disclosed separately on the leaderboard.

WorldOracle uses one evaluation framework across two data distributions: human-operated trajectories and policy rollouts collected on a real robot. The benchmark covers AgiBot G2, YAM, and human-hand embodiments. Choose Main, Policy, or Long-Horizon Track and submit prediction videos; no separate protocol selection is needed.

An uploaded package is not yet a verified benchmark result. Formal queue entry consumes the rolling quota. A successful V number is assigned only after every required metric passes, and only an improved result replaces the model's current leaderboard best.

02 · Eligibility & registration

One account, one registered model.

Create a separate submission account for every model your team enters. Team name, model name, organization, logo and verified email are required. Accounts receive no submission quota until organizer review is complete.

Code, model weights and papers are optional during registration. A model is marked Open Source only after both its public code repository and public model weights are verified. Resource URLs may use any public HTTP/HTTPS host.

After approval, each account may submit up to two evaluations per Track and six evaluations total in a rolling seven-day window. The seven-day window begins with the account's first formal submission and resets the quota for all Tracks together.

More complete information makes approval easier. Use an institutional address where possible and provide public resources that clearly belong to the registered model.

04 · Package specification

Prepare Your Submission

The portal automatically uses the single organizer-approved model bound to this account. Select the Track and platform and optionally add submission notes. Each queue entry receives the next account submission number within its Track. V1, V2, and so on are assigned only after successful evaluations; failed attempts never consume a V number.

Track limits and required coverage

  • Main Track: one ZIP below 3 GiB. Submit the first 30 seconds of every required episode using recorded actions.
  • Policy Track: one ZIP below 3 GiB. Submit the complete policy-distribution rollout for AgiBot G2 and use action_source: policy in the manifest.
  • Long-Horizon Track: one ZIP below 12 GiB. Submit each complete episode using recorded actions; do not truncate it to the Main Track horizon.
Frame rate is platform-specific: AgiBot G2 and YAM use 30 FPS (900 frames for Main); Human Hand uses 15 FPS (450 frames for Main). Preserve the native frame rate and do not duplicate frames.

The limit applies independently to both the uploaded ZIP and the sum of its declared expanded contents. A package may contain at most 20,000 entries. ZIP symlinks, encrypted entries, duplicate or unsafe paths, and a wrapper directory above manifest.json are rejected.

Do not reorder episodes by array position. Preserve the official task / episode_id / view identity and map every video explicitly in manifest.json. Frame indices must be contiguous from zero; synchronized views of an episode must have equal frame counts, frame rates, and durations. Do not select only successful rollouts or silently replace a trajectory.

The implemented schema is preview-2. Set benchmark_track to main, policy, or long_horizon, matching the form. Set evaluation.horizon to 30s, policy, or full; set action_source to policy only for Policy Track and recorded otherwise; and set view_mode to single or multi. Unknown top-level manifest fields are rejected.

Input directory format

submission.zip
├── manifest.json              # Required; metadata and prediction index
├── README.md                  # Required; reproduction and alignment details
├── predictions/               # Prediction MP4 files for the selected Track
│   └── pickfruit/ep000000/top_head.mp4
├── config/                    # Recommended; inference settings and seeds
└── logs/                      # Recommended; generation and evaluation logs

Each prediction entry must include task, episode_id, view, fps, path. The standard output is H.264 MP4, yuv420p, no audio, source resolution preserved, and the platform's native benchmark frame rate. In README.md, explain the action-to-frame mapping, whether the initial frame is included, the original resolution, and any unavoidable resampling.

Required compression profile

Encode the original JPEG or PNG sequence directly to the final MP4. Use libx264, the slow preset, two-pass average bitrate 2830k, yuv420p, a 60-frame GOP, scene-cut disabled, and no audio. Do not create a lossless MP4 first and transcode it again.

The five benchmark baseline packages currently shown for AgiBot G2—IRASim, DreamDojo, Ctrl-World, Cosmos 3, and GE-Sim 2.0—were all encoded at the same target video bitrate: 2830k in both passes. The two ffmpeg commands are the analysis pass and the final-output pass of one two-pass encode, not two different compression settings.

The commands below use 30 FPS for AgiBot G2 and YAM. For Human Hand, change both -framerate values to 15. The example input is one frame_00000.jpg sequence. For six-digit PNG input, use frame_%06d.png.

ffmpeg -nostdin -hide_banner -loglevel error -y \
  -framerate 30 -start_number 0 -i 'frame_%05d.jpg' \
  -map 0:v:0 -an -c:v libx264 -preset slow -b:v 2830k \
  -pix_fmt yuv420p -vsync 0 -g 60 -keyint_min 60 -sc_threshold 0 \
  -pass 1 -passlogfile 'top_head-pass' -f null /dev/null

ffmpeg -nostdin -hide_banner -loglevel error -y \
  -framerate 30 -start_number 0 -i 'frame_%05d.jpg' \
  -map 0:v:0 -an -c:v libx264 -preset slow -b:v 2830k \
  -pix_fmt yuv420p -vsync 0 -g 60 -keyint_min 60 -sc_threshold 0 \
  -pass 2 -passlogfile 'top_head-pass' -movflags +faststart \
  top_head.mp4

2830k is the parameter that primarily controls file size; preset slow controls how efficiently that bitrate is used, not the target size. CRF is not used for the standard package because its final size is content-dependent. The approximate total is bitrate × the sum of all video durations ÷ 8, plus MP4 and ZIP overhead. Use the same bitrate for every view and episode. A single-view submission is therefore smaller than a three-view submission, but each video receives the same compression strength. If the complete ZIP exceeds the Track limit, lower the bitrate uniformly for every video. Record the reduced bitrate in the submission README (README.md).

Package and verify

# Run from the directory containing manifest.json, README.md and predictions/
zip -0 -r submission.zip manifest.json README.md predictions/
unzip -t submission.zip
shasum -a 256 submission.zip

-0 stores the already-compressed MP4 files without wasting time recompressing them. Before uploading, confirm the ZIP is below the selected Track limit and that manifest.json is at the ZIP root. Every Track package must include pickfruit / ep000000 / top_head; if the result becomes that model's leaderboard best, its complete 30-second comparison video is shown publicly. All other package files remain private.

Do not include passwords, API keys, private tokens, personal data, raw GT frames, caches, checkpoints, or unrelated experiment outputs.

Uploads are resumable: the browser sends verified 16 MiB parts over up to 6 parallel lanes. Each part is checked with SHA-256, the assembled ZIP receives a full-file SHA-256, and interrupted uploads can resume by reopening the same draft and selecting the identical ZIP. Incomplete uploads expire after 48 hours.

05 · Submission wizard

Validate and Submit

Use the same validation routine locally before uploading:

python validate_package.py submission.zip

The validator ships with the submission portal source code; its standalone public distribution is pending. In the submission portal, follow four steps:

  1. Model and Track: check your assigned model, choose a Track and platform, and optionally add submission notes.
  2. Upload Materials: choose a ZIP. The browser uploads resumable parts and the background worker checks the assembled package and records its SHA-256 checksum.
  3. Declarations: confirm authenticity, permissions, and the absence of secrets.
  4. Confirm and Submit: check the summary and enter the automatic evaluation queue.

Saved steps remain in your account. After an interruption, reopen the same draft and reselect the identical file to resume. Replacing the package resets its declarations to prevent mismatched submissions. After final submission, the record is read-only unless the organizers request changes.

Track admission checks inspect video headers and decode the first frame, enforce the platform frame rate (30 FPS for AgiBot G2 and YAM; 15 FPS for Human Hand), validate view counts, synchronization, and Main Track's 30-second limit. They do not decode every frame, assess data leakage, recompute metrics, or establish result validity.

06 · What happens next

Evaluation and Publication

Follow progress in My Submissions. The public stages are Draft, Submitted, Evaluating, Review when manual confirmation is required, and Accepted. During Evaluating, the portal shows only overall progress and does not expose which metric is currently running.

DraftSubmittedEvaluatingReview if requiredAccepted

If any evaluated dimension exceeds the current leaderboard top score, publication is paused for organizer review. Otherwise, a successful evaluation is accepted automatically. An accepted result updates the public leaderboard only if it improves the model's current best.

07 · Fair and reproducible

Rules and FAQ

How should unavailable metrics be reported?

Use N/A, with the reason and supported views. A missing or unsupported metric is not a measured zero.

Are submission notes required?

No. Use this optional field for information you want the organizers to know about this submission, up to 4,000 characters.

Can I submit repeatedly?

Each approved account may submit up to two evaluations per Track and six evaluations total in its rolling seven-day window. Failed or incomplete attempts do not consume a V number.

Are my files public?

The original ZIP and all other package files remain private. Only the declared comparison video for a model's accepted leaderboard-best result may be displayed publicly beside its score.

Can I upload only my aggregate scores?

No. All three Track forms require prediction-video artifacts. Self-reported numbers alone are insufficient for evaluation.
